# DHIS2 API Debug Test Plan

## Objective
Test the exact API calls that OpenFN Job 3 makes to identify where the workflow is failing, without running the full workflow.

## Test Strategy

### Phase 1: Connectivity & Authentication
**Goal**: Verify DHIS2 is accessible and credentials work
- Test: `GET /api/me`
- Expected: Admin user info returned
- If fails: Check DHIS2 container, port mapping, credentials

### Phase 2: Category Options Creation
**Goal**: Verify category options can be created
- Test: `POST /api/categoryOptions` (Male, Female)
- Test: `GET /api/categoryOptions?filter=code:eq:MALE`
- Expected: Options created, UIDs returned
- Critical: We need these UIDs for category creation

### Phase 3: Category Creation
**Goal**: Verify categories can be created with options
- Test: `POST /api/categories` with SEX category
- Test: `GET /api/categories?filter=code:eq:SEX` (immediate retrieval)
- Expected: Category created with options linked
- **Critical test**: Can we GET the category immediately after POST?
  - If NO: This explains "No categories found for combination" error
  - Solution: Add delay or retry logic

### Phase 4: Category Combination Creation
**Goal**: Verify category combos are created with option combos
- Test: `POST /api/categoryCombos` with HEALTH_REPORTING_COMBO
- Test: `GET /api/categoryCombos?filter=code:eq:HEALTH_REPORTING_COMBO`
- Expected: Combo created, categoryOptionCombos auto-generated by DHIS2
- **Critical check**: Does response include `categoryOptionCombos` array?
  - If NO: Need different endpoint or wait time
  - If YES: Verify structure matches what Job 4 expects

### Phase 5: Data Element with Category Combo (CRITICAL)
**Goal**: Verify data elements can be assigned custom category combos
- Test A: `POST /api/dataElements` **WITH** `categoryCombo: {id: <combo_id>}`
- Test B: `POST /api/dataElements` **WITHOUT** categoryCombo (default)
- Test: `GET /api/dataElements` for both, compare categoryCombo field
- Expected: Test A has custom combo, Test B has default combo
- **This is THE critical test**: If Job 3 doesn't assign combo to data element,
  all data will use default combo regardless of sex/age group

### Phase 6: Category Option Combo Mapping
**Goal**: Verify we can map sex/age to specific option combo IDs
- Test: Parse categoryOptionCombos from combo retrieval
- Test: Create mapping like `{sex: 'Male'} -> <option_combo_id>`
- Expected: Each option combo has categoryOptions array we can match against
- **Critical for Job 4**: This mapping must exist for buildDataValues()

## Expected Failures to Investigate

### Issue 1: "No categories found for combination"
**Location**: Job 3, line ~496
**Hypothesis**: GET request immediately after POST returns empty
**Test**: Phase 3 - check if category appears in GET after POST
**Fix**: Add retry logic or use response UID directly

### Issue 2: "paging: 'false' vs paging: false"
**Location**: Job 3, multiple GET requests
**Hypothesis**: String 'false' may cause API issues
**Test**: Compare API responses with both formats
**Fix**: Change all to boolean false

### Issue 3: Data Element not using category combo
**Location**: Job 3, createDataElements function
**Hypothesis**: categoryCombo not assigned at creation
**Test**: Phase 5 - verify data element categoryCombo field
**Fix**: Pass categoryCombinationId to createDataElements() and include in payload

## Success Criteria

### Must Pass:
1. All API calls return 200/201 status
2. Categories can be retrieved immediately after creation
3. Category combo includes categoryOptionCombos array
4. Data element WITH categoryCombo has custom combo, not default
5. Category option combos can be mapped to sex values

### Nice to Have:
6. Compare timing between POST and successful GET
7. Document exact response structure for each endpoint
8. Identify minimum required fields for each object

## Next Steps After Testing

1. **If tests pass**: Issue is in Job 3 logic, not DHIS2 API
   - Fix: Update Job 3 to match working test sequence
   
2. **If tests fail at Phase 3**: Category retrieval timing issue
   - Fix: Add retry logic or use POST response UID
   
3. **If tests fail at Phase 5**: Data element combo assignment
   - Fix: Add categoryCombo field to data element creation
   
4. **If all tests pass but workflow fails**: State management issue
   - Fix: Check what's passed between jobs in state object
